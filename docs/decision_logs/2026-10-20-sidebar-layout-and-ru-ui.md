# Решение: вёрстка сайдбара, мобильная адаптация и полный перевод интерфейса

**Дата:** 2026-10-20
**Статус:** Принято

## Контекст
По скриншоту пользователя видно, что чипы уровней (0–10) в сайдбаре выходят за границы панели фильтров: часть кнопок обрезана, горизонтальной прокрутки нет. Проверка показала, что причина системная: **85 utility-классов, используемых в шаблонах, не были определены в CSS** (`flex-wrap`, `overflow-x-auto`, `grid`, `space-y-*`, `mt-*`, `border-*`, `prose` и др.). Классы в стилях написаны в «Tailwind-стиле», но Tailwind в проекте нет — есть самописный `utils.css`.

Из-за этого:
- чипы уровней не помещались в сайдбар;
- хедер выходил за границы экрана на мобильных (документ шире вьюпорта на 63 px);
- таблица заклинаний не прокручивалась по горизонтали на узких экранах;
- на странице «Настройки» оставался английский текст (нарушение требования «интерфейс полностью на русском»);
- `SpellDetailView` при прямом открытии `/spell/:id` всегда редиректил на главную: данные загружаются асинхронно, а `onMounted` проверял наличие заклинания до загрузки списка.

## Альтернативы
1. Подключить Tailwind — отклонено: проект сознательно без него, переписывание разметки слишком рискованно.
2. Оставить одну горизонтальную прокрутку для уровней — отклонено: пользователь попросил упорядочить элементы в области видимости.
3. Починить `SpellDetailView` через `isLoading` — отклонено: `isLoading` на момент `onMounted` ещё `false` (хук родителя вызывается позже), нужен признак «список получен».

## Решение
1. **`utils.css`**: добавлены все недостающие utility-классы (`flex-wrap`, `flex-nowrap`, `items-start`, `justify-end`, `grid`, `grid-cols-2`, `min-w-0`, `overflow-x-auto`, `space-y-*`, `mt-sm/md`, `pt-md`, `py-xs`, `border-b/t/none`, `bg-transparent`, `text-center`, `whitespace-pre-line`, `resize-none`, `accent-*`, `first:*`, `md:grid-cols-4`, `md:col-span-2`). Классы со спецсимволами заэкранированы: `.min-w-\[200px\]`, `.border-\[var\(--color-border\)\]` — без экранирования lightningcss считает `[200px]` атрибутным селектором и падает на сборке.
2. **`components.css`**: добавлен класс `.prose` для HTML-описаний заклинаний.
3. **`AppSidebar.vue`**: блок «Уровень» переведён на CSS-сетку 6 колонок (`grid-template-columns: repeat(6, minmax(0, 1fr))`) — все 11 чипов помещаются в ширину сайдбара (280 px) двумя рядами, горизонтальная прокрутка убрана.
4. **`layout.css`**: `.header-left`/`.search-form` получили `min-width: 0`, `.header-right` — `flex-shrink: 0`; на экранах ≤480 px текст логотипа скрывается (остаётся иконка). У `.spell-grid` добавлен `min-width: 0` для дочерних элементов — иначе широкая таблица растягивала grid-трек.
5. **`SpellDetailView.vue`**: проверка существования заклинания перенесена в `watch([spells, spellId, loadError])` — редирект на главную происходит только после загрузки данных.
6. **Перевод на русский**: страница «Настройки» (Data/Export/Import/Clear/About/Theme/View mode), текст ошибки загрузки, английские `aria-label`. В `translations.ts` добавлены `FILTER_LABELS` и функция `filterLabel()`; значения активных фильтров переводятся через `traditionLabel()`/`schoolLabel()`/`rarityLabel()`/`traitLabel()`.
7. **`stores/index.ts`**: колонка «Классы» убрана из настроек по умолчанию (во всех 2009 записях поле пусто).
8. **`scripts/postbuild.mjs`**: после сборки `dist/index.html` копируется в `dist/404.html`. GitHub Pages отдаёт `404.html` для любого пути, которого нет в репозитории, а SPA-маршруты (`/settings`, `/spell/:id`) физически на сервере не существуют — без `404.html` прямой заход по такой ссылке (или перезагрузка страницы) показывал страницу 404 GitHub вместо приложения. Теперь приложение стартует по запрошенному пути, маршрут разбирает vue-router. HTTP-статус остаётся 404 — это ограничение статичного хостинга, изменить его нельзя.

## Обоснование
Изменения локальные, не меняют структуру данных и не требуют новых зависимостей. Проверено: `lint`, `typecheck`, `test` (10/10), `build`, `check-runtime` (2009 заклинаний, 0 ошибок), `check-dev` (0 ошибок), а также Playwright-прогон на десктопе и мобильном viewport: горизонтального переполнения нет ни на одной странице. На живом сайте проверены `/settings` и `/spell/aonprd-spell-2335` — оба рендерятся корректно.

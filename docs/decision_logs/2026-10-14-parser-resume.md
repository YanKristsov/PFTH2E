# 2026-10-14-parser-resume

## Контекст
Работу продолжили из `RESUME.md` в новой среде Windows. Репозиторий был получен как ZIP, поэтому в рабочей папке нет `.git`; системные Node.js, npm и Git также отсутствовали.

## Согласованные продуктовые решения
- Поиск и фильтрация должны работать мгновенно по локальному каталогу; источник обновляется ежедневно, а не запрашивается при каждом действии игрока.
- Варианты из разных источников показываются равноправно и с явным происхождением.
- Приоритеты проекта: наибольший охват заклинаний и точность правил.
- Следующий рабочий этап: тесты парсера на HTML-фикстурах и аудит покрытия источников.

## Решения

### 1. Запуск TypeScript-парсера
**Проблема:** `package.json` запускал отсутствующий `scripts/parse-spells.js`, тогда как в репозитории есть только `scripts/parse-spells.ts`.
**Решение:** запускать существующий файл через `tsx` и добавить `tsx` в devDependencies.
**Обоснование:** это работает с Node 20, указанным в workflow, и сохраняет TypeScript исходником парсера.

### 2. Защита сгенерированных данных
**Проблема:** исходный парсер при нулевом результате создавал пустые JSON и завершался кодом 0.
**Решение:** не записывать файлы, если после валидации не осталось ни одного заклинания; завершать процесс с ненулевым кодом.
**Обоснование:** ежедневный workflow не должен считать неудачный разбор успешным обновлением каталога.

### 3. Состояние источников
Проверка актуальной разметки показала, что исходные CSS-селекторы устарели: AoN загружает результаты динамически, у русской документации отдельный список `all-spells.html`, а `pf2.ru` помещает JSON двух таблиц в атрибуты `pf2-table[items]`. Активен только `pf2.ru`; детали запрашиваются через его batch endpoint последовательными пакетами по 100 ID для каждого языка.

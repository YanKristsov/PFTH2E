# Решение: рабочий скрипт деплоя без gh-pages CLI

**Дата:** 2026-10-20
**Статус:** Принято

## Контекст
Текущий `npm run deploy` использовал `gh-pages -d dist`, что падало с `ENAMETOOLONG` в этой ветке (много исторических файлов). Также git не в PATH, в PowerShell 5.1 нет `&&`, и нужно правильно очищать старые хешированные ассеты в корне перед копированием.

## Альтернативы
1. Починить `gh-pages` (менее надёжно в Windows с большой веткой) — отклонено
2. GitHub API деплой через `scripts/deploy.mjs` — рабочий, но требует `GITHUB_TOKEN`, сложнее в использовании локально
3. PowerShell-скрипт с прямым git по полному пути + копирование `dist/*` в корень — принято

## Решение
- Создан `scripts/deploy.ps1`: сборка через `npm run build` (с postbuild), очистка артефактов сайта в корне, копирование `dist/*` в корень, удаление `index.dev.html` (не нужен в проде), `git add -A`, коммит, `git push origin gh-pages --force` через полный путь к git.
- В `package.json` `deploy` заменён на вызов скрипта.
- Удалён неиспользуемый `scripts/deploy.mjs` (API-вариант).
- Из деплоя убран `parse:spells` (данные в репозитории, избежание зависимости от внешней сети).
- При деплое удаляются ненужные для сайта файлы конфигурации/шаблоны из корня при добавлении.

## Обоснование
Простота, предсказуемость, не требует токенов, работает в PowerShell 5.1, корректно обрабатывает Windows пути.

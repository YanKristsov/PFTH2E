# Agents.md — Принципы работы с Kilo Code

## Общие принципы

### 1. Формат интервью для сбора требований
- **Раунды по 3-5 вопросов** с 6 вариантами ответа (A-F) каждый
- После каждого раунда — **фиксация решений** в таблице
- **Не переходить** к реализации, пока не закрыты все неопределённости
- Вопросы "почему" и "зачем" — обязательны для серых зон

### 2. Дробление задач
- Одна задача = один логический шаг (проверяемый локально)
- Использовать **todowrite** для отслеживания прогресса
- Подагенты (`task` tool) для параллельного исследования/поиска
- Не пытаться сделать всё за один ответ

### 3. Документирование решений
- **Все решения** → `/docs/decision_logs/YYYY-MM-DD-short-title.md`
- Формат: контекст, альтернативы, решение, обоснование
- Обновлять соответствующие docs-файлы (architecture, api, data-model)
- `decision_log` — источник правды для истории проекта

### 4. Качество кода
- **Локально проверяемо**: `npm run lint`, `npm run typecheck`, `npm run test`
- TypeScript strict mode — обязательно
- ESLint + Prettier — настроены и запускаются в CI
- Коммиты только после прохождения проверок

### 5. Стек технологий (зафиксирован)
| Категория | Выбор | Причина |
|-----------|-------|---------|
| Бандлер | Vite | Скорость, простота, PWA плагин |
| Фреймворк | Vue 3 + Composition API | Проще для новичка, меньше boilerplate |
| Язык | TypeScript | Типы для данных заклинаний критичны |
| Состояние | Pinia | Простое, типизированное, девтулсы |
| Роутинг | Vue Router 4 | Стандарт для Vue |
| Поиск | MiniSearch | Лёгкий полнотекстовый поиск в браузере |
| Валидация | Zod | Схемы для парсеров и API |
| PWA | vite-plugin-pwa + Workbox | Авто-генерация SW, офлайн из коробки |
| Хостинг | GitHub Pages | Бесплатно, отдаёт корень ветки `gh-pages` |
| Деплой | Ручной, скриптом в `RESUME.md` | Без Actions: файлы копируются в корень ветки |
| Парсинг | Node.js скрипты в `scripts/` | Данные в репо, история изменений в git |

### 6. Архитектура данных
- **Один JSON** (`public/spells.json`) — ~500 заклинаний, ~80 KB gzipped
- **Схема Zod** — единый источник типов для парсеров и фронта
- **Конфликты источников** → массив вариантов с пометкой источника
- **Поля**: ru/en названия, уровень, традиция, школа, классы, traits, компоненты, описание, heightened, источник, rarity

### 7. UI/UX требования
- **Интерфейс полностью на русском.** Переключатель языка удалён; английским остаются только оригинальные названия заклинаний и названия источников
- **Словарь переводов** — `src/constants/translations.ts` (традиции, школы, редкость, черты, компоненты). Компоненты используют функции `traditionLabel()`, `schoolLabel()`, `rarityLabel()`, `traitLabel()`, а не прямые обращения к константам
- Адаптивно: таблица (десктоп) ↔ карточки (мобайл), переключатель вида
- Дерево навигации: Традиция → Школа → Уровень (сайдбар)
- Детальная страница: вкладки «Кратко» / «Полно»
- Поля для фильтров: уровень, традиция, школа, класс, traits, компоненты, источник, rarity
- Полнотекстовый поиск по названию + описанию + traits
- PWA: офлайн, иконка на рабочем столе, авто-обновление

### 8. Расширенный функционал (после MVP)
- Избранное + заметки к заклинаниям (localStorage)
- Экспорт/импорт JSON (бэкап, миграция)
- История просмотров (последние 20)
- Сравнение заклинаний (2-3 в модалке)
- Горячие клавиши (/, f, esc, стрелки)
- Настройки: тема, колонки таблицы

### 9. Деплой (РУЧНОЙ, без GitHub Actions)
- **Ветка `gh-pages` — источник правды**: в ней и исходники (`src/`), и собранный сайт
- GitHub Pages отдаёт файлы **из КОРНЯ ветки** → после сборки `dist/*` копируется в корень, `dist/` удаляется из индекса git
- Подробности команд: `RESUME.md`, раздел «Деплой»
- **Vite 8 (rolldown)**: не авто-инжектит `<script type="module">` в HTML — нужен явный тег
- **Шаблон HTML — `index.dev.html`, а не `index.html`**: корень `index.html` занимает прод-сборка (её отдаёт Pages). `vite.config.ts`: `build.rollupOptions.input = 'index.dev.html'`, плагин `devHtmlPlugin()` отдаёт этот шаблон в dev, `scripts/postbuild.mjs` переименовывает `dist/index.dev.html` → `dist/index.html`. Использовать корневой `index.html` как Vite-input нельзя — падает `Failed to resolve /PFTH2E/assets/index-*.js`
- **Парсеры**: Node.js скрипты в `scripts/`, проверка runtime через `scripts/check-runtime.ts` и `scripts/check-live.ts` (Playwright)

### 10. Приёмка работы
Критерии для каждого этапа:
1. `npm run dev` — запуск без ошибок
2. `npm run build` — успешная сборка в `dist/` (проверить, что в `dist/index.html` есть `<script src="/PFTH2E/assets/...">`)
3. `npm run parse:spells` — создаёт валидный `public/spells.json`
4. Функционал работает: поиск, фильтры, детали, навигация
5. PWA: работает офлайн (DevTools → Application → Offline)
6. `npx tsx scripts/check-runtime.ts` — 0 console errors, 0 failed requests
7. Деплой проходит, `npx tsx scripts/check-live.ts` подтверждает: сайт доступен на `https://yankristsov.github.io/PFTH2E/`
